LAPTOP.

A Slack bot of your own that runs Claude Code or Codex on your Mac, in your repo, with your own logins.

Start setup ↓

Why this exists

Your best agent setup is on your laptop: the repo with your uncommitted work, Claude Code logged in to your tools, your skills. Your questions arrive in Slack, often when you're away from that laptop. Nothing official connects the two.

Official optionRuns onWhat's missing for this
Claude in SlackAnthropic's cloudWorks on a fresh copy of the repo from GitHub, without your local tools or uncommitted work. Team and Enterprise plans, set up by a workspace owner. Channel replies are public.
Claude Code on the webA cloud machineThe same: GitHub repos only, none of your local logins.
Remote ControlYour MacYou drive it from the Claude app or website, not Slack, and only a session you already started.
Codex in SlackOpenAI's cloudCloud tasks, not your machine.

laptop-assist is the missing piece: the question comes in through Slack, your own Mac does the work with the same agent you use at your desk, and the answer goes back to Slack. Use the official options when you want one shared bot for a whole channel, or long jobs that keep running with your laptop closed; this one sleeps when your Mac does.

How it works

There's no shared bot. Everyone runs their own copy, and each copy talks to exactly one person.

Slack You DM your bot It answers your Slack account only and ignores everyone else.
Your Mac A restricted agent starts Claude Code or Codex, in your repo. A background program that starts at login picks the message up over a connection your Mac opens to Slack, so nothing on your laptop is reachable from the internet.
Thread The answer lands in the thread Reply there to keep going in the same conversation.

It uses your accounts

Claude runs count toward your own Claude plan; Codex runs toward your ChatGPT plan. Anything it posts to GitHub goes out under your gh login.

It sleeps when your Mac does

With the lid closed the bot is offline. When it reconnects it picks up the messages you sent it in the meantime (your recent DMs, and replies in threads from the last three days).

What it can and can't do

Slack becomes a remote control for your laptop, so the limits matter more than the features.

Only you

It ignores every message, reaction and button press that isn't from your Slack account.

Read by default

A new question can look but not change anything. Write is a choice you make per thread, and even then it never pushes, merges or approves.

Nothing posted as you without your say-so

Slack drafts appear only to you and go out only when you press Send as me. GitHub comments and reviews happen only in a write thread you started, when you ask for them (for review drafts: reply write, then post inline).

Nothing reachable from the network

Your Mac connects out to Slack. The only listener is a small local dashboard on 127.0.0.1, reachable from this Mac alone.

Where your data goes

Your question, the Slack messages it reads and the code it looks at go to Anthropic or OpenAI, under your plan, exactly as when you use Claude Code or Codex yourself. Nothing goes to the author of this tool. Update checks ask GitHub for the latest release, with your own gh login.

Tokens stay in the Keychain

Your Slack tokens live in the macOS Keychain, never in a file. Logs and history stay in ~/.config/laptop-assist on your Mac.

One honest caution: the agent reads things other people wrote (Slack threads, PRs, issues). Someone could write instructions meant to steer it. Read threads can't change anything, so they're safe for that. In write threads, check what it plans to change before you let it commit, and keep write threads for your own work.

Install and set up

About 10 to 15 minutes once you have access. Have these ready: access to two private repos, a Slack workspace that lets you add apps (or an admin who will approve it), and the repo you want the bot to work in.

  1. 01

    Get access

    laptop-assist is an internal tool, maintained by @aldefy. The code and its Homebrew tap (the source Homebrew installs it from) are private. Send your GitHub username and ask for read access to aldefy/laptop-assist and aldefy/homebrew-private.

    GitHub emails you two invitations. Accept both before installing, or the install fails with "Repository not found".

  2. 02

    Check your Mac

    macOS only. Run each check in a terminal:

    Homebrew installed (prints a version)brew --version
    Claude Code installed; then run claude once and log in if askedclaude --version
    GitHub CLI logged in (says "Logged in")gh auth status
    SSH key on GitHub (greets you by username)ssh -T git@github.com
    Optional: Codex, logged in, for the Codex agentcodex --version

    No SSH key yet? Run ssh-keygen -t ed25519, then gh ssh-key add ~/.ssh/id_ed25519.pub. If your GitHub organization uses single sign-on, authorize the key for it on github.com. Already use Sentry, Crashlytics, Jira, Mixpanel or the Slack plugin in Claude Code? The bot reuses those logins, read and query tools only. Other tools you use in Claude Code can be allowed later with laptop-assist tools.

  3. 03

    Install

    brew tap aldefy/private git@github.com:aldefy/homebrew-private.git
brew install laptop-assist
  4. 04

    Create your Slack app

    laptop-assist setup

    Setup first checks for Claude Code, which is required (it stops if missing), then git and gh. Then it creates your Slack app with you:

    1. It asks what to call your bot and suggests a default with your first name. This is the name you'll see in Slack, and the message-menu item becomes Ask <that name>.
    2. It opens Slack's "create an app" page in your browser with a ready-made manifest (the app's name and the permissions it needs). If you're signed in to several workspaces, pick the right one. Click Next and Create.
    3. Click Install to Workspace, then Allow. If your workspace requires admin approval, Slack shows "request sent" instead: leave setup and run it again after approval.
    What the app is allowed to do, and a message for your admin

    As a bot: read and reply in your DM with it, add and read reactions, upload long answers as files, look up people by name and email, read threads in channels it's invited to, and post in public channels (only used if you opt in to the weekly usage line). With your user token, if you add it: post as you (only when you click), read the conversations you're in when you ask about them, remove your own reactions, and search your messages (for catch-up and the opt-in voice note).

    Hi! I'd like to install a personal Slack app called "<your bot's name>" (made with the laptop-assist tool): a bot only I can talk to, which runs Claude Code or Codex on my own laptop and answers in my DM with it. It never posts on its own; anything posted as me needs my explicit action. Could you approve it when the request comes in?

    Next, setup asks for three tokens. Leave the Slack page open; each one is a long string you copy and paste into the terminal. You won't see anything as you paste: that's normal, just press Return.

    1. App-level token
    xapp-…

    Left sidebar Basic Information, scroll to App-Level Tokens, Generate Token and Scopes. Any name; add the connections:write scope; Generate.

    2. Bot token
    xoxb-…

    Left sidebar OAuth & Permissions. Copy the Bot User OAuth Token.

    3. User token, optional
    xoxp-…

    Same page, User OAuth Token. Without it: no Send as me, draft emoji, morning catch-up or voice; asks can't read conversations the bot isn't in; and only-you answers land at the bottom of the conversation. Add it later with laptop-assist user-token.

    Treat tokens like passwordsDon't paste them into Slack, a ticket or a file. Keep the app's Collaborators list to just you. You can revoke them any time from the same Slack pages.
  5. 05

    Finish setup

    1. It finds your Slack account from your git email and asks you to confirm. If it can't, it asks for your member ID: in Slack, your profile, the ⋯ menu, Copy member ID.
    2. It asks for the repo the bot should work in (the full path, like /Users/you/code/app), and explains read and write.
    3. It lists extra tools from your own Claude Code settings that you could allow. If you're unsure, press Return to skip; laptop-assist tools does it later.
    4. It asks three quick questions you can leave on their defaults: the draft emoji (default ▫️, called white_small_square), your terminal, and the morning catch-up time (09:00, or off). Each is explained further down.
    5. It runs a self-test (about $0.10 of Claude usage). It asks the read-only agent to write a file. That should be refused; if the write works, setup stops, because the safety limits aren't working.
    6. It installs the background program so the bot starts whenever you log in, and offers the menu bar icon.

    Settings live in ~/.config/laptop-assist/config.json. Run laptop-assist setup again any time; it keeps your answers. Change single settings with laptop-assist set.

  6. 06

    Say hello

    In Slack, find your bot under Apps (or search for its name) and send it something that needs only your repo:

    summarize the last 3 commits

    A card appears in the thread. Pick what you need, then press Run:

    • Skill (optional, empty to start): skills are reusable instructions you've added to Claude Code (in ~/.claude/skills or your repo's .claude/skills). The list shows yours, best matches first, plus "No skill".
    • Agent: Claude by default. This row appears only if Codex is installed on your Mac.
    • Read or write: Read is preselected.

    Skip the card by starting a new message with read: or write: (or codex read: / codex write:). Name a skill directly with / and its exact name. In a thread you can also send stop (cancel the run), read or write (switch mode), codex or claude (switch agent). Anywhere: status, version, update, catch up. Every answer ends with how long it took and, when available, its cost and model; answers longer than Slack shows are attached as a file.

Read or write, Claude or Codex

Each thread runs in one mode with one agent. Read and Claude are the defaults.

With ClaudeReadWrite
Read code, search, git log, diff and blameYESYES
Query Sentry, Crashlytics, Mixpanel, Jira; read SlackYESYES
Edit files; git add, commit, fetch, switch branchNOYES
Run unit tests and compile (out of the box: the Android/Gradle tasks; other test commands via laptop-assist tools)NOYES
Comment on a PR, post a review with inline commentsNOYES
Extra tools you allowed with laptop-assist toolsREAD TOOLSYES
Push, delete files, reset, run other shell commandsNONO
Approve or merge a PRNONO

Codex works differently. It can run any command, but inside its own sandbox: in a read thread nothing on disk can change; in a write thread it can change files inside the repo only, with network access off, so it can't push. The bot doesn't give it your Sentry, Jira or Slack tools, and it can't post to GitHub. Codex runs have no dollar cap, only the time limit.

There's no full-access mode in Slack on purpose: an unrestricted session you can drive from Slack would be a remote shell into your laptop. The bot can see a list of your other Claude Code sessions on this Mac (to answer "what are my sessions doing?") but can't send them anything.

Replies without copy and paste

A teammate asks you something. The bot reads the conversation, drafts a reply only you can see, and posts it as you only when you click. All of this works best with the user token.

Message menu
⋯ → Connect to apps

On any message, then Ask <your bot's name>. Works in DMs with other people too.

Emoji
React with your draft emoji

▫️ (white_small_square) unless you picked another. The bot removes your reaction right away.

Morning
Catch-up at 09:00

Weekdays: up to 8 threads from the last day where someone mentioned you and you haven't replied, each with Draft reply. Send catch up for it any time.

You decide
Send as me

Or Edit and send, or Dismiss. Nothing goes out without your click.

From the message menu

  1. Hover over the message and click ⋯ at the end of the small toolbar.
  2. Choose Connect to apps ›, then Ask <your bot's name>. If it isn't there the first time, reload Slack with Cmd+R.
  3. A pop-up shows the message. Type what you want ("draft a reply", "is this fixed on main?") or leave it blank, and click Ask.
  4. In a minute or two, an answer marked Only visible to you appears: inside the thread if the message was in one, otherwise at the bottom of the conversation. The full run stays in a thread in your DM with the bot, where you can follow up.

Messaging someone

Send your bot message <their name>: <your text> and the send card appears straight away. Or ask it to write one ("message Priya that the build is out") and check the draft. It sends to people, not channels or groups; if several people match the name, you get a card for each, so press send on the right one.

Your voice, if you want it

Run laptop-assist voice to have it read your recent Slack messages and write a short note on how you write. You see the note and approve it before drafts use it; only the note is kept (voice --show, voice --delete). Off until you run it.

Drafts see the thread or DM they came from, including what you already said there. In channels you've invited the bot to, you can also @-mention it in a thread, but your message is visible to everyone. Slack doesn't let bots into DMs between people, so use the message menu there. Answers marked Only visible to you disappear when Slack reloads; the copy in your DM with the bot stays.

Review drafts, then post

When someone requests your review on GitHub, a draft review shows up in your DM with the bot. Nothing reaches GitHub until you say so.

Bot
Draft arrives

In read mode. Findings with file and line, plus a verdict.

You
write

Switches the thread so it's allowed to post.

You
post inline

Or ask for changes first: "drop finding 3, then post inline".

GitHub
One COMMENT review

Never an approval or a change request.

Before anything goes up, it checks that the PR hasn't moved past the commit it reviewed and that every inline comment points at a line inside the diff. If a check fails, it posts nothing and tells you which comments to fix.

The bot checks GitHub every few minutes with your gh login. It also DMs you when CI fails on one of your PRs (reply investigate). Automatic drafts stop at 10 a day. Turn either off with laptop-assist set reviewDrafts off or laptop-assist set ciAlerts off.

Slack to terminal, and back

Some answers are too long for Slack, and some work is easier at a keyboard. Every answer has a Continue in terminal button that opens the same conversation on your Mac.

Slack
Continue in terminal

On any answer. The bot also suggests it when an answer was cut short or a run didn't finish.

Your Mac
Same conversation opens

A new window or tab in your terminal, in your repo, with everything so far.

Meanwhile
Slack waits

Replies in that thread say it's open in your terminal instead of starting a second copy.

Done
Back in Slack

Quit, or close the window. The thread gets a note, and your next reply there carries on from what you did.

In the terminal it's your normal Claude Code or Codex, with your usual permissions, not the restricted Slack mode: you're at the keyboard.

Pick your terminal

Setup asks which one you use. Change it any time:

laptop-assist terminal <name>

Run it without a name to see what's installed and what's set. With nothing set it uses the first installed of cmux, iTerm, Ghostty, WezTerm, kitty and Terminal. If one can't open, it tries the next; as a last resort it posts the command in the thread for you to paste.

The menu bar icon (optional)

The bot runs in the background with no window, so you can't tell at a glance whether it's up or busy. SwiftBar is a small, free, open-source Mac app that lets tools put an item in the menu bar; laptop-assist uses it for a status icon.

What it shows

Whether the bot is running; each question in progress with its agent, its last few steps as they happen, and a stop button; runs and cost for today and the week; your last 10 questions, each with Open thread and Continue in terminal; and buttons to restart, open the log and open a local dashboard.

Do you need it?

No. Everything works without it. laptop-assist status shows whether it's running and what's in progress, and sending status to the bot shows today's runs and cost.

Setup offers to install it. To add it later:

brew install --cask swiftbar
laptop-assist install-menubar

The icon refreshes every 10 seconds from files on your Mac, so it doesn't talk to Slack or cost anything.

When it breaks

Common problems, roughly in the order people hit them.

brew tap says "Repository not found" or "Permission denied (publickey)"

An invitation isn't accepted yet, or GitHub doesn't have your SSH key. ssh -T git@github.com should greet you by username. To add a key:

ssh-keygen -t ed25519
gh ssh-key add ~/.ssh/id_ed25519.pub
Slack says "request sent" when you click Install

Your workspace requires admin approval for new apps. Send your admin the message under step 04, then run laptop-assist setup again once it's approved.

Setup rejects a token, or the bot logs "invalid_auth"

The three tokens look alike, so it's easy to paste one into the wrong prompt. App-level starts with xapp-, bot with xoxb-, user with xoxp-. Run laptop-assist setup again and paste each into its own prompt.

The bot never replies

Run laptop-assist status and laptop-assist logs and look for laptop-assist up. If it's up: check that setup confirmed your Slack account, and that the app-level token has connections:write. If Slack says "Sending messages to this app has been turned off", open your app's App Home page and turn on the Messages tab.

Every answer fails with a login or "not authenticated" error

The background program uses the same Claude Code login as your terminal. Run claude in a terminal, log in, then laptop-assist restart.

Your bot DMs you about new Slack permissions

Some updates add features that need more permissions. Until you do this, everything else keeps working.

  1. Run laptop-assist manifest "your bot's name". It copies the new manifest to your clipboard.
  2. On api.slack.com/apps, open your app, then App Manifest in the left sidebar. Select all the text in the box, paste, Save Changes.
  3. Install App in the sidebar, Reinstall to Workspace, Allow. Your workspace may ask for approval again.
  4. Copy the User OAuth Token from that page and run laptop-assist user-token.
"Ask <your bot>" isn't in the ⋯ menu, or @-mentions do nothing

Reload Slack with Cmd+R. If it's still missing, your app needs the current manifest (the item above). For @-mentions, invite the bot to the channel first.

Only-you answers appear at the bottom of the conversation, not in the thread

Expected for a message that isn't in a thread. For one that is, it happens when the bot isn't in that conversation and you haven't added the user token: add it with laptop-assist user-token.

The bot doesn't start right after an update

macOS sometimes stops the first launch of a freshly updated program. Run laptop-assist restart, twice if needed.

Sentry, Jira or another tool isn't available

The bot only reuses tools you've already connected and logged into in Claude Code. Log in there, then laptop-assist restart. Tools beyond Sentry, Crashlytics, Mixpanel, Jira and Slack need laptop-assist tools.

Posting a review fails with "PR head is now …"

Someone pushed after the draft was written. Ask it to re-read the diff and re-check its comments, then say post inline again.

Questions people ask

Can a teammate use my bot?

No. It ignores everyone but you, so they set up their own. Each person's bot has its own name, so several can live in one workspace.

Does it post anywhere on its own?

Never to anyone but you. It messages you in your DM with it (answers, review drafts, alerts, catch-up), and answers it shows elsewhere are visible only to you. Anything posted as you needs your explicit action: a click in Slack, or post inline for a GitHub review. The only automatic post is the weekly usage line, and only if you turn it on.

What will it cost?

Claude runs count toward your Claude plan and share its usage limits with your normal Claude Code use. Each one is capped at $2 by default (up to $5) and times out after 10 minutes (up to 20). Codex runs use your ChatGPT plan and have only the time limit.

Can it work on more than one repo?

One repo per install. Run laptop-assist setup again to switch.

What does it keep?

Run history, logs and settings in ~/.config/laptop-assist and ~/Library/Logs/laptop-assist.log, on your Mac only. Logs include the first part of each question.

How do I remove it?

Run laptop-assist uninstall (service, Keychain items, menu bar icon, log, and your settings if you say yes), then brew uninstall laptop-assist, then delete your app on api.slack.com (your app, Basic Information, Delete App).
