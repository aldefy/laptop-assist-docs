1. How it works

Everyone runs their own copy. There is no shared bot.

SlackYou DM your own bot app. It only listens to your Slack member ID; anyone else is ignored.
Your MacA small background service receives the DM over an outbound websocket (no public URL) and starts a locked-down Claude Code run.
ReplyThe answer comes back in the same thread. Replying in the thread continues the same Claude session.
  • Your bot, your account. It runs with your Claude login, so usage counts against your Claude plan.
  • Who it posts as. In Slack it only posts in your DM with your bot. On GitHub (write threads only) it posts as whoever is logged into gh on your Mac, so it's you.
  • Mac asleep means bot offline. Messages sent while the lid is closed are picked up when it reconnects.

2. Get access

The code and the Homebrew tap are private repositories. Send your GitHub username to @aldefy and ask for read access to:

  • aldefy/slack-claude (the code)
  • aldefy/homebrew-private (the Homebrew tap)

Accept both invitations (GitHub emails you, or check notifications) before you install.

4. Install

brew tap aldefy/private git@github.com:aldefy/homebrew-private.git
brew install slack-claude

If the tap fails with Repository not found or Permission denied (publickey), your access invite isn't accepted yet or your SSH key isn't on GitHub. See Troubleshooting.

5. Create your Slack app

Each person creates their own app from the same manifest.

5.1 Copy the manifest

slack-claude manifest

This prints the manifest and copies it to your clipboard.

Give your bot a unique nameBefore pasting, change name and display_name from Claude Laptop to something like Claude (Priya). Otherwise the workspace fills up with identical "Claude Laptop" apps.

5.2 Create the app

  1. Open api.slack.com/apps and click Create New App.
  2. Choose From a manifest, pick your workspace, select YAML, paste, click Create.
  3. Click Install to <workspace>, then Allow. If your workspace needs admin approval for new apps, this step waits for an admin.

5.3 Collect the two tokens

  1. App-level token: Basic Information → App-Level Tokens → Generate Token and Scopes. Add scope connections:write, generate, copy the xapp-… value.
  2. Bot token: OAuth & Permissions → copy the Bot User OAuth Token (xoxb-…).

5.4 Lock it down

  • Collaborators: keep it to just you.
  • Interactivity & Shortcuts: should already be On from the manifest (it powers the Read/Write buttons).

Treat both tokens like passwords. Don't paste them in Slack, tickets or files.

6. Run setup

slack-claude setup

It walks through six steps:

  1. Checks that claude, git and gh are on your PATH.
  2. Slack tokens: paste the xapp-… and xoxb-… tokens. Input is hidden; they're stored in the macOS Keychain, never on disk.
  3. You: your Slack member ID. In Slack: your profile → ⋯ → Copy member ID (looks like U0123ABCD). This is the only person the bot will answer.
  4. Repo: the absolute path of the repo Claude should work in, e.g. /Users/you/code/app.
  5. Self-test (about $0.10): one real, locked-down Claude run. It tries to write a file and refuses to finish setup if the write succeeds.
  6. Service: installs a background service that starts at login. Optionally adds a menu-bar icon (needs brew install --cask swiftbar).

Config lands in ~/.config/slack-claude/config.json (repo path, per-message budget up to $5, timeout up to 20 min, dashboard port).

7. Use it

Open Slack, find your app under Apps, and DM it. Examples:

top 5 Sentry issues in the last 24h
review PR 1285 with android-pr-review
what are my other Claude sessions doing?
  • New DM = new question. Reply in the thread for a follow-up with the same context.
  • stop in a thread cancels the run. status reports health.
  • Each answer ends with time, cost, tokens, turns and model.
  • React 👍 or 👎 on answers; the local dashboard tracks quality.
  • Local dashboard: http://127.0.0.1:7317 (only reachable from your Mac).

8. Read and write threads

Every thread is either read or write. A new DM asks which (buttons, or reply read / write). Start a DM with read: or write: to skip the question. mode shows the current one; replying read or write switches.

Read (default)Write
Read code, search, git log/diff/blameyesyes
Query connected tools (Sentry, analytics, Jira, Slack read)yesyes
Edit files, local git add/commitnoyes
Run unit tests / compilenoyes
Comment on a PR, post a COMMENT review with inline commentsnoyes
Push, delete files, reset, arbitrary shell, approve or merge PRsnono
Message or drive your other Claude sessionsnono

There is deliberately no "full access" mode: an unrestricted session driven from Slack would be a remote shell.

9. PR review drafts and posting

When someone requests your review on GitHub, the bot DMs you a draft review. Drafts never post anything on their own. Bot-started threads begin in read mode.

To publish it:

  1. Reply write in the draft's thread.
  2. Reply post inline (or ask for edits first, e.g. "drop finding 3, then post inline").

The bot posts a single review with event COMMENT (never approve or request changes). Before posting it checks that the PR hasn't moved past the commit it reviewed and that every inline comment sits on a changed line. If any check fails, nothing is posted and it tells you which comments to fix.

Big PRs: the diff is read file by file, so line anchors come from the real diff, not a truncated one.

11. Troubleshooting

brew tap: Repository not found / Permission denied (publickey)

Accept the invites to both private repos, and make sure ssh -T git@github.com greets you. If you use HTTPS-only GitHub auth, add an SSH key: gh ssh-key add ~/.ssh/id_ed25519.pub.

The bot never replies

  • Run slack-claude status and slack-claude logs. You should see slack-claude up.
  • Check the member ID in setup is yours (the bot ignores everyone else).
  • Check the app is installed to the workspace and the app-level token has connections:write.

Service won't start right after an upgrade

macOS sometimes kills the first launch of a freshly upgraded binary. Kick it once or twice:

launchctl kickstart -k gui/$(id -u)/dev.slack-claude

Read/Write buttons do nothing

Turn on Interactivity & Shortcuts in your Slack app. Typing read or write in the thread always works.

A tool (Sentry, Jira…) isn't available

The bot only reuses MCP servers you've already connected and logged into in Claude Code. Log in there first, then slack-claude restart.

"PR head is now …" when posting a review

New commits landed after the draft. Ask it to re-read the diff and re-check its comments, then post again.

12. FAQ

Can teammates use my bot?

No. It ignores every message and reaction that isn't from your member ID. Each person sets up their own.

Does it post to Slack channels or on my behalf?

No. It only replies in your DM with your own bot. GitHub comments (write threads only) appear under your gh account.

What does it cost?

It uses your Claude plan. Each message has a budget cap (default $2, max $5), runs stop after 10 minutes by default, and automatic runs (review drafts, CI alerts) are capped at 10 per day.

Is anything exposed to the internet?

No inbound ports. Slack Socket Mode is an outbound websocket; the dashboard binds to 127.0.0.1 only. Slack tokens live in the Keychain.

How do I remove it?

slack-claude stop
brew uninstall slack-claude
brew untap aldefy/private

Then delete your Slack app at api.slack.com/apps and remove ~/.config/slack-claude.
